## Running the actual interface

Serve the repository with the existing TTL/STOP server and open `workbenches/fire-realism/index.html`. The interface loads the actual driver and `mountUI`, with one selected render and the existing six-button HUD. The public package excludes workbenches, reference photographs, review tools and documentation. Calling the package private in a build log describes exclusion; the GitHub repository itself is public.

- Modes: published current fire, detailed reference, optimized, and the identical no-fire control. Availability and exact reasons come from the driver. Missing optimized art stays unavailable.
- Scenarios: match, carried torch, gasoline, gasoline with powder, wall-clipped jet and Catalogue Street. Powder is an actual simulation scenario; the UI never multiplies its clocks. Only driver-declared cases offer 32/128/512 initial ignitions; actual burning counts are reported separately.
- Configuration: isometric/oblique, bright/dim, seed, native animal, canvas preset and pixel ratio. The driver validates these values. Mode/view/lighting/viewport changes rebuild and replay to the same frame. New scenario/seed/animal/population starts again. Manual HUD input changes the live run, so reset before a matched comparison.
- Transport: play, pause, reset, single step and deterministic seek. The outer workbench is the pause indication.
- JPEG capture: calls the driver's actual `captureFrame` and retains up to six captures. Each figure has expandable exact metadata without the image payload. Separate Save JPEG and Save evidence JSON buttons download the image and its exact configuration, tick, source fingerprints and hardware record, one file per gesture. A missing WebGL canvas cannot produce a capture. Images are not synthetic evidence.
- Raw report: after measurement retires, prepare the complete unchanged driver report once as exact JSON plus LF. An expandable disclosure and explicit Save report data link expose identical UTF-8 bytes, byte count and SHA-256. The 32 MiB limit, missing digest and preparation errors are explicit; no truncated summary replaces the report. Prepare raw report retries an actual idle report, including cancelled/inconclusive status. No automatic download occurs.
- Cost: invokes the driver's selected matched modes; default warm-up/sample/trial settings remain entirely in the driver. Cancel stays enabled while the measure promise is pending and calls `cancelMeasurement` immediately. Raw reports preserve source/hardware/canvas/workload information and rejected data. The UI displays supplied medians/p95/variance/ratios; it computes none of them and never approves a target from a number.

The page explains the fixed authoritative-pose benchmark separately from live motion. Sustained emission in that benchmark is an explicit adaptation. Live spread, powder timing, finite burnout and played motion still require separate review. A fitted preview scales the canvas and HUD together; actual-size inspection preserves authored CSS dimensions inside a scrollable viewport. Match the browser viewport to the canvas preset for actual HUD breakpoint review. A phone-shaped canvas is not phone hardware.

The separate [cold delivery boot](delivery-boot.md) resolves the one optional fixed repository descriptor before importing the driver or public-art dependency graph. Descriptor 404 retains explicit unconfigured debug/null arguments; configured errors stop startup with an unavailable shell. No actual descriptor, pin or receipt is added by that wiring.

## Bounded live motion export

The controls are Record live motion, Stop recording, and Discard. They feature-detect the actual canvas's `captureStream` and `MediaRecorder` and start real driver playback. A nominal ten-second timer requests a stop; callback scheduling and encoder drain can extend actual wall time. The recorder reports actual elapsed time, stop-request time, timer scheduling overrun, encoder drain and total overrun without changing the simulation clocks. The legacy `maximumDurationMs` field remains a compatibility alias for the nominal timer, not a hard wall-clock guarantee.

Completion performs no download. The latest complete actual encoded WebM/MP4 clip is retained as one explicit **Save video** link plus a paused `preload="none"` preview. Its video data URL comes only from the actual encoder Blob. Retention is limited to 16 MiB of encoded video, with a size-checked base64 representation; a larger recording retains its exact metadata and explains why the preview/link is unavailable. The separate Save motion metadata button downloads the JSON on another explicit gesture. The same exact metadata is expandable next to the clip and remains in the source disclosure and critique export: source fingerprints, identified hardware, configuration, actual canvas, requested capture rate, encoded bytes, actual timing and authoritative start/end clocks/workload. The requested 60 Hz capture rate is not measured frame rate. A paused still cannot become motion evidence.

The preview never autoplays. Before GPU measurement enters the driver, the UI locks evidence controls, pauses the preview, removes its source and calls `load()` to retire media resources. The explicit save link is unavailable during measurement or recording. Recovery restores the link and a paused, non-preloading source; it does not resume playback. Recording still excludes GPU measurement and scene changes. Only the actual WebGL canvas is recorded; DOM HUD readability needs separate browser evidence. No camera, microphone or desktop capture is requested.

Only one clip and one owned FileReader can be retained. Replacement, reset, abort and disposal cancel any pending read, remove its listeners, clear the old link/preview source and release the old state references. Generation checks suppress late asynchronous publication. Per-clip and per-gallery listeners are retired on replacement, so removed figures cannot accumulate attached handlers. The stream and every track belong to the recorder: stop/discard/abort/dispose, hidden tabs, encoder errors, start failures, the nominal timer and the existing 64 MiB recorder safety bound retire tracks. A missing stop event has a bounded five-second drain before unavailable status. Ordinary JSON/image download object URLs retain their existing short cleanup path. No video object URL, external recorder library or helper process is introduced.

The implementation follows the documented [canvas capture API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream) and [MediaRecorder API](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder). No external recorder library or copied example is included.
