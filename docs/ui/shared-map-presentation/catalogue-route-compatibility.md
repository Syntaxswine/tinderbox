# Catalogue route compatibility — frozen source audit

Scope: production Catalogue Street visits selected through the title/menu, read at architect pin [`cd443ccdd9cbbb38cf4c338ef697d902739726d6`](https://github.com/Syntaxswine/tinderbox/commit/cd443ccdd9cbbb38cf4c338ef697d902739726d6). All file/line references below use that pin, not moving root HEAD. Evidence is delivered on `codex/shared-map-tools-ui` from `8f0cd5743d159c53f56eeeb4eabd137cd3d7621c`; no runtime intake or implementation is included.

Production auto-start calls `startApplication`, whose Catalogue branch calls `catalogueVisit(search)`, optionally loads the modular package/wind, then calls the existing `createRuntime` with `createArtScene` and `mountUI`. The four requested routes therefore share the host and HUD factory. [Entry and factory](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/main.js#L47-L85)

## Common controls and authoritative state

All four Catalogue routes advertise `{version:1,mode:'gameplay',tools:true,health:true,interact:true,overview:false}`. M29 `gameplayMap` instead selects the same flags with `overview:true`. The host passes the factory ceiling to `mountUI`; snapshots cannot change its mode or grant a disabled capability. `uiOptions.mode` cannot grant M29 overview. [Factory selection][sim], [capability records/ceiling][caps], [host mount][host], [UI validation](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/ui/model.js#L90-L108)

Tool IDs remain `matches`, `jerry-can`, `molotov`, `torch`, `flamethrower`; the display labels remain Oil barrel for `jerry-can` and Oil lantern for `molotov`. The deck stays left Matches/Torch/Flamethrower, right Oil barrel/Lantern/Menu. UI queues `select-tool` before `primary`; simulation owns stock, ignition, torch lifetime, pour trail and lantern aim/projectiles. Native providers receive `heatTool`/`cone`/`impactLantern`; older providers receive their existing field/cottage/housing calls. Walk-over drugs/medicine remain simulation-owned; no manual drug control is added. [Tool ABI](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/config.js#L27), [UI tool labels](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/ui/model.js#L1-L7), [deck and action order](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/ui/index.js#L29-L43) (`133–160` for action/cancel), [tool providers](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/tools.js#L13-L76) (`132–185` for held/projectile paths), [movement/pickups/clocks](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/index.js#L306-L331).

## Concrete M29 connections still absent

1. **Catalogue factory → M29 map adapter:** none of these four routes calls `createSharedMapRuntime` or supplies `gameplayMap`/`createMapStructureArt`. At this pin only New York enters that factory; `MAP_SOURCE_PINS` contains only `new-york`, and other place IDs are rejected. Default/witness already share `createSceneThermal` through the Catalogue compatibility wrapper, so absence of the new factory is not absence of shared tool/thermal code. [Production dispatch][entry], [M29 runtime](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/runtime/shared-map.js#L7-L20), [thermal wrapper](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/catalogue-thermal.js#L1-L5)
2. **Context → map definition/provider:** `createSimulation` rejects `gameplayMap` together with `scenario`, `catalogueModules` or `cottageWind` (`src/simulation/index.js:31`). The current generic `gameplayMapDefinition` seeds empty actors, pickups, modules and buildings; it does not carry Catalogue's witness marker, patrol/resident/shop setup or cottage comparison automatically. `compileSharedMap` exposes `sampleWind`/`windMetadata`, but the production M29 loader currently supplies neither. A Catalogue conversion therefore has an explicit, presently unconnected context boundary; removing query arguments would lose their meaning. [Simulation boundary][sim], [empty map definition](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/content/shared-map-pilot.js#L36-L38), [compiled hooks](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/content/shared-map.js#L14-L29), [M29 runtime](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/runtime/shared-map.js#L17-L20)
3. **Physical publication → structural presentation/navigation:** Catalogue emits `catalogueModules`; M29 emits `scene` plus `navigation`. The art owner selects separate module/map/cottage/legacy consumers; `createMapStructureArt` requires `snapshot.scene.scene.version===1`. M29 also selects simulation source picking, section-ready navigation and map-provider disposal; Catalogue uses module/cottage art picking and its existing movement provider. The UI-owned `createSharedMapPresentation` is a strict pass-through requiring a map and structural factory, not a converter for these records or a new HUD. [Publication](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/index.js#L375-L399), [art updates](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/art/index.js#L130-L155), [map frame requirement](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/art/shared-map.js#L35-L44), [provider navigation](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/simulation/scene-thermal.js#L99-L110), [host picking/disposal][host], [presentation adapter](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/runtime/shared-map-presentation.js#L5-L13)
4. **Capabilities/lifecycle are already connected through the common host:** no extra tool-ID translation or UI frame loop is missing. Any later factory conversion must preserve its authoritative ceiling and original ownership: application epoch/abort/dispose and pending-load retirement; host cancel/pause on blur/hidden page, snapshot clocks, UI/art/simulation disposal and provider cleanup. The app supplies the same selected native character and visit signal to each route. [Application lifecycle](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/runtime/application.js#L8-L40), [host lifecycle][host], [art ownership/cleanup](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/art/index.js#L191-L203)
5. **Direct `startGame` is a different entry:** its exported helper calls `createRuntime` with `scenario:'neighborhood'` and caller overrides; it never parses the URL or loads modules/wind. It must not be used as evidence for production-menu query behavior. Production auto-start uses `startApplication`. [Both entries](https://github.com/Syntaxswine/tinderbox/blob/cd443ccdd9cbbb38cf4c338ef697d902739726d6/src/main.js#L18-L47) (`84–85` for auto-start).
