## Corrected presentation

The curved lattice has 2,016 submitted triangles per instance and eighteen procedural interior density samples per covered volume fragment. Its geometry/noise supports view-dependent silhouette and rolling density gaps. Flame colors now use a bounded linear palette with the published host's **NoToneMapping/sRGB** output; the fixture no longer relies on ACES/exposure to produce a different result. Smoke/brightness/motion are uncalibrated artistic choices that still need actual animated critique.

Every flame, smoke, jet, torch and building instance belongs to one shared transparent draw stream. Instances sort back to front by camera-space source centroid with semantic-ID ties. Equivalent source-array order produces identical accumulation, point-light selection and geometry. A paused camera change re-sorts the unchanged sources. There is no fixed smoke-after-flame layer order. **Centroid sorting remains approximate for intersecting transparent volumes.** It is not exact order-independent volume compositing; reversed-camera/overlap views must be judged in a real render before acceptance.

The marcher samples a borrowed same-frame opaque scene depth and stops interior density accumulation when it reaches that depth. Hardware shell depth testing alone is not described as sufficient. The factory validates the declared WebGL depth convention, matrix/dimension shapes, actual camera view-projection agreement and physical size `floor(CSS size * pixelRatio)`. It binds these inputs before the paused early return. Missing or mismatched input is diagnosed as unavailable occlusion and uses shell testing only; it never claims a passed depth case. The runtime owner is responsible for the actual same-frame prepass, visible/alphaTest material behavior, transparent/faded exclusions, hiding all fire and including prepass cost in the GPU query. A CPU test proves binding/ownership, not visible occlusion or correct GPU samples.

Connected ordered discharge uses the exact resolved fan and forward-start rule. The visible native muzzle is used only when it lies inside that fan. A short resolved fan outside the muzzle retains the existing control's `shapeOrigin` support/start-zero behavior and is no longer omitted. `connectRays:false` uses distinct procedural vertical ribbons on the exact clipped ray lines, without filling unsafe triangles between them. These exceptional ribbons are explicitly a surface fallback, not full 3D jet volumes. The common lattice's unused half-ring degenerates for a ribbon; submitted-triangle diagnostics include those vertices and do not claim all triangles contribute silhouette. Valid `lead.from/to` is presented separately. None of these paths alters ray endpoints, fan reach, heat, collision or native attachment geometry.

An isolated liquid-fuel jet now emits bounded dark soot from observed resolved-ray positions, with a small near-source puff and terminal-region rolls informed by the distinct Navy/portable images. Historical source positions are retained only when actually observed on a new world-time sampling bucket. Smoke moves upward on world time and expires after3.2 world seconds; missing frames do not invent unobserved past muzzle paths. This is a presentation adaptation, with no obstacle-flow solver. Current opaque depth handles visible intersections; actual wall-edge behavior still needs review.

Building presentation consumes only the coder's documented `buildingVisuals` records. It requires a real non-destroyed group with measured bounds and at least one supplied burning ID that belongs to both its collider footprint and the actual current burning cells. At most four observed sources per group attach flames/smoke to the nearest ground-floor facade. This coarse adaptation adds **no roof or upper-floor heat state**; unrelated nearby grass, stale/spent IDs and placeholder records cannot ignite a facade. The separate runtime component preserves legacy Molotov/barrel transients explicitly; this factory does not duplicate or claim ownership of those events.

## Frame and ownership

`createFireRealism(THREE,{quality:'reference',maxCells:4096,maxRays:256,maxBuildings:64})` returns `{root,update,reset,dispose,diagnostics}`. `quality:'optimized'` throws until a legitimate reference is visually accepted and frozen. Input grids support65,536 cells; emitting/history sources are bounded to4,096, rays to256, building groups to64 and jet-smoke records to384. Overflow throws rather than dropping visible fire. The defaults and all resource limits are explicit diagnostics. The host supplies its shared Three r180; the factory creates no renderer, loader, fetch, absolute donor path or simulation state.

All effect positions use native metres at an identity root: ground(x,y) maps to Three(x,height,z). `update` consumes the detached milestone-11 v1 frame, existing cell states, native anchors and authoritative resolved discharge. Camera arrays are column-major. `fieldUniforms` and optional `opaqueDepth` textures are borrowed, never cloned per frame or disposed by the effect. All matrices/settings copied into owned uniforms are detached. Repeated update/reset uses the same one geometry, one material and two owned data textures; the three spill lights are bounded. Disposal is idempotent and frees only owned GPU resources.

Motion uses `worldTime`, never wall/player time. Pause freezes emission and the clock while accepting the current camera/depth; reset, rewind and receipt-generation/reset clear source histories. Spent fuel stops flames and its3.2-second smoke tails expire. A torch requires **selected tool `torch`**, a finite lit timer and a supplied actual torch-tip anchor. Retained lit inventory state cannot display an unequipped torch. Runtime event receipts remain external to this art factory.
