# Lazy receipt bridge: next isolated implementation

This selects the UI specialist's 17 November read-only recommendation as the
next coder stage **after the current query parity correction passes review**.
Reuse the existing coder checkout/branch. It advances the regional compiler and
effective-query work toward M29; it is not a four-map or production acceptance.

Start with cold source geometry and zero precompiled native inventory. Add a
producer-owned authenticated query slice of a guarded compiler receipt,
incremental query admission and one coordinator publishing a complete
`{generation, revision, stockSnapshot, queryView}` state. The compiler/ledger and
kernel must prepare complete next states before mutation. Final validation and
synchronous publication must not leave hidden claims advanced when another
participant rejects. Independent existing `commit()` calls are insufficient.
Keep the coordinator disabled and out of live factories/registries/consumers.

The slice validates the real private receipt capability and retains immutable
original geometry references, IDs, physical bounds, channels, metadata and
source/cell provenance. Omit live scene references and `heatCells`; do not feed
guarded boundary records unchanged through a generic freezing path. Bind the
slice to its producer, epoch, source revision, grid, owner and exact original
descriptor/part-cell intersection. Neither caller-supplied `complete: true`,
zero fuel nor an empty list proves complete empty coverage. The producer must
attest completion of its original restricted compiler loops, including cells
that emit no query records. Keep cold, complete-empty native and retired states
distinct. Preserve canonical stock/quantity certificates, original native IDs,
halo replicas, primitive geometry and all current tolerances/limits.

Document ownership transfer: producer owns pending receipts; successful
publication retains immutable query geometry for held views; ledger holds
numeric claim metadata. Failed stages release their own resources without
discarding caller-owned work. Unified reset/disposal invalidates capabilities,
pending stages and held views, releases generation-born inventory and preserves
the original cold source. Named-record retirement must retain other records in
the same cell. Foreign/stale/duplicate/overlapping claims must fail atomically.

Use small synthetic compiler fixtures first: disjoint claims, authenticated
complete-empty cells, original reference/ID/quantity agreement, forged/foreign/
stale/incomplete inputs, disposal between prepare/publication, injected
preparation failures, held views, reset and record-local retirement. Retain the
original query controls and exact ten hostile repros. Avoid a broad new fuzzer.

Then at most **three original roof-region compilations in one finite process**:
two disjoint nonempty regions and one empty region selected from the already
pinned roof catalogue. Compare their original records, borrowed geometry,
quantities and query domains; demonstrate distant regions remain cold. Record
the exact descriptor choices and bounded launch/cleanup. This is a new tiny
bridge check, not permission to replay the spent full-roof/960-call proof,
compile the deck or create another whole-geometry snapshot. If an empty
catalogue region is not actually available, report it and retain synthetic
complete-empty evidence rather than manufacturing a receipt.

The native floor's approximately .12 m below-surface solid exceeds its assigned
cell's existing halo and remains unsupported. Another catalogue stratum does
not fix that record's ownership. Preserve a rejecting control; do not shift
IDs, slice original solids, widen limits or silently claim floor integration.
General floor representation and support-port/birth integration remain later
gates. No world/trial/support graph, live adapter, renderer, browser, benchmark,
build, other-map export or new dependency is included. Keep evidence compact,
preserve all prior archives/WIP, run relevant checks/declaration, scoped
commit/push and stop for architect review.
