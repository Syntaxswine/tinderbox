## Static diagnosis and candidate correction

The archived support adapter cleared each authored cell in `originalCore` unless
that endpoint already had a native record in `nextFixed`. Once a regional owner
was touched, its remaining cold material was divided into component/cell/island
fragments. An unborn endpoint on a cell boundary could then match two cold
fragments, and the core correctly reported `ambiguous-original-port-owner`.

[The red regression](synthetic-cold-cell-red.json) captures that failure with only
tiny fixture geometry. The unchanged roof point `[1.5,0,0.25]`, authored cell
`[3,0,0]`, matched both cold cells `[2,0,0]` and `[3,0,0]` while a distant region
was staged. The roof port became non-live while the other two ports stayed
live. The fixture has at most 64 source cells and 256 triangles.

The candidate retains the reviewed cell as an ephemeral selector for an unborn
endpoint of a touched regional owner. It does not store that selector as a native
binding, change the endpoint or select a new cell. A later genuine receipt still
binds the same authored cell to its actual native record. The green regression
checks that transition and verifies that retirement then loses the fixed port.
No point, primitive, selector, tolerance, anchor or source asset was changed.

Metadata identifies New York `legacy-pair-018` as a plausible instance: its cold
roof witness has X `55.5`, exactly on the 0.5 m grid, with reviewed cell
`[111,16,118]`, outside the first staged domain. This is a static hypothesis,
not a recovered actual diagnosis. The staged failing port list was not retained,
so other causes remain possible. Actual coupled acceptance is still blocked.

The updated harness saves the complete first regional inspection and checkpoints
it to disk before testing port liveness. It also retains the whole and adjacent
stage inspections. The original source snapshot, launch/preflight, stdout and
result are unchanged. New metadata preflights write `candidate-preflight.json`
after a launch exists, and the consumed run guard executes before readiness work.
