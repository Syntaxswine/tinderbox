## Packet and boot contract

`codec.js` is original shared source, copied byte-for-byte into the generated closure. Every scalar packet starts with three u32LE values: magic `0x31505a46` (`FZP1`), word count and packet count. Each run has a u32LE tag: high bit means literal, low 31 bits are a positive count. A zero run omits only words whose bits are `0x00000000`; a literal run copies exactly count*4 original bytes. Negative zero, subnormals, NaN payloads and all other bit patterns remain literal. Maximal alternating runs and complete/trailing-byte checks make decoding deterministic. Native gzip compresses packet bytes, not quantized floats.

Generated `registry.js` owns metadata and one `createPayloadRuntime(metadata)` instance. Each static `chunk-NNN.js` imports that registry and top-level awaits `runtime.append(id, base64Gzip)`. The runtime serializes sibling module work; it does not decompress all chunks concurrently. Each stream writes into the single bounded sparse byte store, checks gzip/packet hashes, decodes one channel for an independent original-channel SHA check and then releases that temporary ownership. `index.js` statically imports every chunk, calls `finish()` after their awaits, and exports synchronous `createFireFluidPayloadFixture()` and `payloadDiagnostics()`. No per-frame operation is asynchronous.

The fixture is deliberately one live owner per module. `frame(number)` or `framePair(a,b)` decodes from shared sparse packets into exactly two reusable dense frame buffers. Returned channel byte views are borrowed, f32LE, and invalid after eviction/disposal; callers must not retain or mutate them as immutable snapshots. A second owner requires disposing the first. Disposal drops owned dense buffers; another owner reuses the same shared sparse payload without another inflation. This is plumbing, not a final renderer or multi-patch API.

Hard limits are 64 MiB aggregate asset ESM source, 96 MiB decoded sparse packets, 256 payload chunks, 2 MiB source per chunk and 4 MiB decompressed packets per chunk. Grouping targets 256 KiB sparse per chunk; it is not a source-size goal. A dense frame is capped at 16 MiB, with at most two such buffers owned. Any excess rejects the probe rather than truncating data. Source text/module cache, shared sparse bytes, compressed/stream/verification scratch, and current/next dense buffers are reported separately. Explicit buffer counters are ownership/allocation evidence, not browser resident RAM: compiled code, strings, gzip/crypto internals, delayed GC and externally retained borrowed views are unmeasured.
