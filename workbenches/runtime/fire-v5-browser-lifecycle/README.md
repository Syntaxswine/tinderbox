# V5 browser lifecycle audit

This QA-only page uses the existing strict delivery loader and the architect’s current `workbenches/fire-realism/delivery.json`. It changes no asset, descriptor, renderer or loader. Serve the repository using the architect’s existing finite preview and open `/workbenches/runtime/fire-v5-browser-lifecycle/`. This worker does not start that server or browser.

Use one fresh document per case, click **Run lifecycle audit**, export the exact visible textarea JSON, and close the document. The host permits one attempt, a cooperative 180-second deadline, bounded staging polling, and clears its timer/listener handles in `finally`.

- `?case=cancel-staging`: the supported loader import hook performs native `import(url)`, retains its exact namespace and returns it unchanged. The loader invokes it only after all configured JS/resources/receipts have verified. Page code polls real exported evidence while loading is pending. It aborts only after observing `ready=false`, positive staged bytes and at least one verified scalar. Passing requires an actual `AbortError`, zero shared/staged/dense payload ownership immediately and after three bounded event turns. Pre-import cancellation, completed preparation, observer failure or missing staging evidence cannot pass.
- `?case=success-lease`: complete the real 193/579 preparation. Call the native exported RGBA audit for its first frame/current-next pair, then stop that audit with its own signal. Its existing `finally` must dispose exactly two RGBA CPU slots (7,077,888 bytes) back to zero. This does not repeat the 579-channel audit, retain borrowed arrays, create a renderer or claim texture/GPU disposal. The 98,362,125-byte immutable shared packet store remains document-owned until document retirement.

Rejected loads expose no selected verified fingerprint or private loader-buffer counter. Keep unavailable values null; retain the exact import URL, native payload source/resource identities and bounded rejection/cleanup-error tree. Root’s separate descriptor/intake evidence binds the configured commit. Successful loads include the actual issued fingerprint and detached loader metadata. Explicit counters do not establish physical GC/RSS release. This page is a lifecycle proof, not visual, performance or R/O acceptance.

`tests/integration/fire-v5-browser-lifecycle.test.mjs` checks the host protocol with clearly synthetic loader/namespace doubles. Those checks cannot establish native-browser cancellation; the architect must run this exact committed page against the actual configured asset. No test double is supplied by `browser.js`.
